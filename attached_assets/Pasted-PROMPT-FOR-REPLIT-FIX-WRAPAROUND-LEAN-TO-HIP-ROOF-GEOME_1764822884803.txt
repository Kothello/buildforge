This is the triangular hip panel between the main lean-to and the side child.

Understand the intended geometry

The intent:

Each lean-to roof is a single plane (for single-slope).

At a corner, two such planes intersect along a line (the hip).

The hip triangle should:

Start at the building corner (highest meeting point of the two inner roof edges).

End at the outer corner where both lean-tos meet (lowest of the two outer roof edges).

The existing code attempts this using:

thisInnerY, thisOuterY for the current lean-to.

otherInnerY, otherOuterY for the other lean-to.

sharedCornerHighY = max(thisInnerY, otherInnerY).

sharedCornerLowY = min(thisOuterY, otherHeight).

The bug comes from:

Using mixed local/world coordinate assumptions and sign flips (zSign, baseZSign) that produce a triangle that does not lie exactly in the two roof planes.

Refactor to a robust, geometric approach

Replace the current hip triangle construction with a simpler, explicit calculation:

For each hip (corner), determine three world-space points:

P_high: intersection of the two inner roof edges at the building corner.

P_thisOuter: outer roof edge endpoint of the main wraparound lean-to.

P_otherOuter: outer roof edge endpoint of the side child lean-to.

These three points must lie on both roof planes by construction.

Implementation path:

For each lean-to (leanTo and otherLeanTo), compute the four roof corner points in world space:

Reuse or properly use the existing helper:

const computeLeanToRoofCorners = (
  leanTo: typeof leanTos[0],
  position: [number, number, number],
  rotation: [number, number, number]
) => { ... }


If it’s currently unused, start using it:

Pass the same position and rotation that you use when placing that lean-to’s roof group.

Have it return:

innerLeft, innerRight, outerLeft, outerRight as THREE.Vector3s in world space.

For the active corner ('left' or 'right') and the front/back wall:

Pick the appropriate inner/outer corners from each lean-to’s roof:

For example, for a front wall, right corner:

Main lean-to:

P_thisInner = innerRight

P_thisOuter = outerRight

Side child:

P_otherInner = the inner corner adjacent to that corner.

P_otherOuter = corresponding outer corner.

Determine:

P_high = point with larger Y between P_thisInner and P_otherInner.

P_low1 and P_low2 as the outer corners P_thisOuter and P_otherOuter.

Optionally clamp heights if needed to avoid exceeding main roof, but keep them on their respective planes.

Construct the hip triangle geometry directly from those three points:

const vertices = new Float32Array([
  P_high.x,   P_high.y,   P_high.z,
  P_low1.x,   P_low1.y,   P_low1.z,
  P_low2.x,   P_low2.y,   P_low2.z,
  // Optional bottom face if you want thickness
  P_high.x,   P_high.y - roofThickness,   P_high.z,
  P_low1.x,   P_low1.y - roofThickness,   P_low1.z,
  P_low2.x,   P_low2.y - roofThickness,   P_low2.z,
]);

const indices = new Uint16Array([
  0, 1, 2,
  3, 5, 4,
  0, 3, 4, 0, 4, 1,
  1, 4, 5, 1, 5, 2,
  2, 5, 3, 2, 3, 0,
]);


Keep the existing thickness/UV logic, but tie it to these vertices.

You can still offset slightly inward (extensionAmount) to avoid z-fighting, but avoid large fudge factors that twist the panel.

Remove or simplify the old sharedCornerHighY / sharedCornerLowY / baseZSign logic only in the hip section. Do not touch unrelated lean-to code.

Keep UVs & materials similar

Preserve:

hipScale, uRepeat, vRepeat idea for UVs.

Use the same material as other roof panels:

meshStandardMaterial with roofColor, metalness, roughness, and bumpMap.

Only adjust UV coordinates as necessary to match the new vertex order.

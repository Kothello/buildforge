GOAL

Give ADMIN and MANAGER users a clean way to assign leads to reps:

1) Bulk assignment (select multiple leads → assign to rep)
2) Per-row quick assign

We MUST reuse the existing “assigned user” field that already controls what appears in /sales (“My Leads”). No schema changes.

STEP 1 – Discover existing assignment field

- Inspect shared/schema.ts and storage/routes to find the field used for ownership, e.g.:
  - assignedUserId, ownerUserId, closerId, etc.
- Do NOT rename or change that field; just reuse it.

STEP 2 – Bulk selection UI on /leads (client/src/pages/leads.tsx)

1. Add a checkbox column:
   - Header checkbox = select/deselect all rows currently rendered.
   - Row checkbox = toggles that lead’s ID in a `selectedLeadIds: string[]` state.

2. When `selectedLeadIds.length > 0`, show a small control bar above the table:
   - A dropdown of reps to assign to:
     - Use existing `/api/users` or whatever users hook you already have.
     - Filter to `role === "REP"` (and optionally MANAGER if that makes sense).
   - Primary button: **“Assign to Rep”**.

3. Behavior when clicking “Assign to Rep”:
   - If no rep is selected, show a validation error/toast and do nothing.
   - Otherwise:
     - For each selected lead ID, call the existing PATCH `/api/leads/:id` endpoint.
     - In the payload, set ONLY the assignment field you discovered (e.g. `assignedUserId`) plus anything else the endpoint already expects.
     - It’s fine to use Promise.all to run them in parallel.
   - While running:
     - Disable the button and show a loading state (“Assigning…”).
   - On success:
     - Clear `selectedLeadIds`.
     - Invalidate/refetch the leads query so the table updates.
     - Show success toast like: “Assigned 7 leads to Jordan”.
   - On error:
     - Show an error toast with a generic message (e.g. “Failed to assign some leads”).

STEP 3 – Per-row quick assign

1. In the Actions column (or a new narrow column), add a subtle button/icon like a user-switch.

2. Clicking it opens a small popover or dialog:

   - Shows current assignee (name or “Unassigned”).
   - Dropdown of reps (same list as bulk).
   - “Save” button.

3. On save:
   - Call PATCH `/api/leads/:id` with the new assigned user ID.
   - Show loading state on that dialog’s button while it’s running.
   - On success:
     - Close dialog.
     - Invalidate/refetch leads query, or optimistically update that row.

STEP 4 – Permissions / visibility

- **Only ADMIN and MANAGER** should see:
  - The checkbox column

  - Per-row quick-assign button

- Reps:

  - `/sales` (My Leads) must remain unchanged, except that after assignment they naturally see new leads that have been assigned to them.

GOAL

Fix the Delete User flow in CRM Settings so that:

Clicking “Delete” in the confirmation dialog actually calls DELETE /api/users/:id.

The UI uses React Query’s loading state (isPending) instead of a separate isDeleting state, so the “Deleting…” button never gets stuck.

On success:

The user is removed from the list (by refetching /api/users).

Both dialogs close.

On error:

The button goes back to normal (no permanent “Deleting…” state).

An error toast is shown.

If the error is “Cannot delete your own user account” we keep the special message:

title: "You can't delete your own account"

description: "Log in as a different admin to delete this user."

1. Normalize the delete mutation (client/src/pages/crm-admin.tsx)

In crm-admin.tsx, find the existing deleteUserMutation (React Query useMutation). Replace it with this shape (adapt to your file’s imports and toast helper):

const deleteUserMutation = useMutation({
  mutationFn: async (id: string) => {
    // apiRequest already throws on non-2xx. No need to parse JSON.
    await apiRequest("DELETE", `/api/users/${id}`);
  },
  onSuccess: () => {
    queryClient.invalidateQueries({ queryKey: ["/api/users"] });
    setShowDeleteConfirm(false);
    setDeleteText("");
    setEditingUser(null);
    setIsUserDialogOpen(false);
    toast({
      title: "User deleted successfully",
    });
  },
  onError: (error: any) => {
    const message = String(error?.message ?? "Unknown error");

    if (message.includes("Cannot delete your own user account")) {
      toast({
        variant: "destructive",
        title: "You can't delete your own account",
        description: "Log in as a different admin to delete this user.",
      });
    } else {
      toast({
        variant: "destructive",
        title: "Failed to delete user",
        description: message,
      });
    }
  },
});

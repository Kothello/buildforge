GOAL

There are two menus: Leads and My Leads.

Leads = admins/managers see all leads and can assign them to specific users.

My Leads = each user only sees leads where they are the assigned rep.

If a lead is not assigned to the current user, it must not appear in My Leads.

1. Add an assignedToUserId field to leads

Open the shared schema file that defines the leads table (likely shared/schema.ts or similar).

Add a nullable foreign key field to link a lead to a user:

Name: assignedToUserId

Type: string/UUID matching your users table primary key.

Foreign key reference to the users table if the schema tooling supports it.

Example (adapt to existing style):

assignedToUserId: varchar("assigned_to_user_id", { length: 255 }).references(() => users.id).nullable(),


Create or update the migration for this schema change so the database has the new column.

Make sure the Lead TypeScript type exposed to the client includes assignedToUserId?: string | null.

2. Update lead API to support “my leads” and assignment

Find the server route that handles GET /api/leads.

Extend it to support a query parameter mine=true:

Get the current authenticated user (whatever auth helper you already use).

If req.query.mine === "true":

Filter leads where assignedToUserId === currentUser.id.

Otherwise, keep existing behavior (return all leads, or whatever it currently does).

Allow admins/managers to set assignedToUserId:

In the route that handles PATCH /api/leads/:id (or equivalent):

If the request body contains assignedToUserId, only allow this change when the current user has role admin or manager (use your existing role/permission system).

For non-admins, ignore or reject changes to assignedToUserId.

Optionally, add a helper endpoint if it’s cleaner, e.g. POST /api/leads/:id/assign, but re-use the existing auth/DB stack.

3. Filter My Leads to only show assigned leads

Open the React page/component used for the My Leads menu item (this was previously showing all leads assigned to the user; in code it’s probably something like client/src/pages/sales-dashboard.tsx or a similar file).

Find the React Query hook that fetches leads, e.g.:

Change the request it makes so it calls the API with mine=true, for example:

URL: /api/leads?mine=true

Query key: ["/api/leads", "mine"] or similar, so it’s distinct from the “all leads” query.

Do not implement any client-side filter based on assignedToUserId; the server must enforce this with the mine=true logic.

Result: the My Leads page will now only receive leads where assignedToUserId matches the logged-in user.

Open the React page used for the general Leads list (not “My Leads” – the one where admins/managers see everything).

On successful mutation:

If the lead was just assigned to the current user, it appears in My Leads.

If it was reassigned away from the current user, it disappears from My Leads.

Only render the assignment UI for users with admin or manager role. For other roles, they should see the leads but not be able to reassign them.

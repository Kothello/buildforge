    const isManager = role === "MANAGER";
    const isRep = role === "REP";

3. Add route guards for admin-only pages on the client

- Identify the routes that render admin/manager-only pages:

  - All Leads view (e.g. /leads or /sales/all-leads)
  - CRM Settings / Users (e.g. /crm/admin)

- Implement a small ProtectedRoute component OR inline checks:

  Example ProtectedRoute:

    function AdminOrManagerRoute({ children }: { children: React.ReactNode }) {
      const { user } = useAuth();
      const role = user?.role;
      const isAdminOrManager = role === "ADMIN" || role === "MANAGER";

      if (!user) {
        return <Navigate to="/login" replace />;
      }

      if (!isAdminOrManager) {
        // Optionally trigger a toast "Access denied – managers/admins only"
        return <Navigate to="/sales" replace />;
      }

      return <>{children}</>;
    }

- Wrap admin pages in this guard when defining routes in App.tsx (or wherever your routes live):

  <Route
    path="/leads"
    element={
      <AdminOrManagerRoute>
        <AllLeadsPage />
      </AdminOrManagerRoute>
    }
  />

  <Route
    path="/crm/admin"
    element={
      <AdminOrManagerRoute>
        <CrmAdminPage />
      </AdminOrManagerRoute>
    }
  />

- For REP users:
  - If they manually type /leads or /crm/admin:
    - They must be redirected to /sales.
    - Optional: show a toast "Access denied – only managers and admins can view that page."
  - Implement the toast only if you already have a toast system in place; do not introduce a new third-party library.

4. Enforce the same rules on the server

- Open server/routes.ts.

- Identify routes that return admin-level data:

  - All leads list:
    - Example: GET /api/leads
    - Distinguish between:
      - “my leads” (per-rep) endpoint: often GET /api/leads?mine=true or a dedicated route.
      - “all leads” endpoint: returns every lead.

  - User/CRM management routes:
    - Example: GET /api/users, POST /api/users, DELETE /api/users/:id, etc.

- Ensure each admin-level route uses both:
  - authMiddleware(storage) (or equivalent) to authenticate.
  - A role check to restrict to ADMIN or MANAGER.

- If there is already a requireRole or similar helper, reuse it:

  Example:

    app.get(
      "/api/leads",
      authMiddleware(storage),
      requireRole("ADMIN", "MANAGER"),
      async (req, res) => {
        // return all leads
      }
    );

- If the same route currently branches based on user role (e.g. “if query.mine → only mine, else all”), refactor explicitly:

  - Use one code path for “my leads” that allows REP:
    - Example: GET /api/leads?mine=true
      - authMiddleware(storage) only, no requireRole
      - uses req.user.id to filter to leads assigned to that user.

  - Use another code path for “all leads” that only ADMIN/MANAGER can access:
    - Example: GET /api/leads?scope=all or just GET /api/leads without mine=true
      - authMiddleware(storage) + requireRole("ADMIN", "MANAGER")

- For users / CRM settings routes:

  - Enforce:

    app.get("/api/users", authMiddleware(storage), requireRole("ADMIN", "MANAGER"), ...);
    app.post("/api/users", authMiddleware(storage), requireRole("ADMIN", "MANAGER"), ...);
    app.delete("/api/users/:id", authMiddleware(storage), requireRole("ADMIN", "MANAGER"), ...);

- Make sure a REP hitting those endpoints receives:
  - HTTP 403 Forbidden (or 401 if your convention is unauthorized), not full data.
